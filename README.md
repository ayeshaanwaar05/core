# S1 core — group integration

The five-stage RV64 core assembled from the individual stage modules, with an
integration test that runs it against **spike**.

## Layout

```
rtl/
  pkg/s1_pkg.sv       shared types and constants; compiled before everything else
  common/*.sv         platform-shared modules (meds_s1_sram), same path as upstream
  modules/*.sv        one file per module, one module per file
  top/s1_core.sv      the integrated core -- wires the modules together and
                      exposes everything external as ports
simulation/
  tb_s1_core.sv       integration testbench
  tb_s1_hazard.sv     unit testbench for the hazard unit
  rv64i.s             the test program, in assembly
  gen.py              builds the image and the expected results from the toolchain
  prog.svh            GENERATED by gen.py, and committed
Makefile              lint, generate, test
```

## Running it

```bash
make lint     # elaborate and lint the RTL
make test     # build and run the integration test
make test-unit  # build and run the unit testbenches
make prog     # regenerate simulation/prog.svh after editing rv64i.s
```

**Run against the version the MEDS-S1 gate installs, not whatever is local:**

```bash
podman run --rm -v "$PWD:/w:z" -w /w \
  --entrypoint /bin/bash docker.io/verilator/verilator:v5.020 \
  -c 'make lint && make test'
```

Verilator 5.020 rejects SystemVerilog that newer versions accept, and in one
case miscompiles it silently: writing one element of an *unpacked-array input
port* reads as zero in the DUT, with no warning. A clean run on a newer
Verilator therefore proves nothing about the gate.

Current state on 5.020:

```
make lint   lint clean
make test   retired 55 of 55 program instructions, then spun 3 times
            === PASS : 399 checks ===
```

## How the test is trustworthy

Nothing in the expected results is hand-written.

```
simulation/rv64i.s
    │  riscv64-unknown-elf-gcc -march=rv64i -Ttext=0x80000000
    ▼
  rv64i.elf ──► objcopy -O binary ──► 63 instruction words  → imem
    │
    └────────► spike --isa=rv64i --log-commits ──► 55 expected retirements
                                                   (pc, insn, rd, value, next pc)
    ▼
simulation/prog.svh
```

The image comes from `objcopy`, the expected retirement stream from spike's
commit log. A bug in the testbench cannot agree with a matching bug in the core,
because neither side authored the answer.

`make prog` needs the RISC-V toolchain and is a **host** step; `make test` needs
only Verilator. That is why `prog.svh` is committed — the simulation runs on a
machine with no toolchain, and inside the Verilator container.

## Coverage

**39 of 39** RV64I instructions, excluding:

| Excluded | Why |
|---|---|
| 11 loads and stores | no LSU — not this group's module |
| `ecall`, `ebreak` | need a trap handler in the program; next step |

## What is deliberately absent

Three things the core declares as external and this repo does not build. They are
**tied off** in the testbench, not stubbed, because no instruction in the test
program reaches them — and the testbench asserts they were never used:

| Ports | Block |
|---|---|
| `dmem_*` | the D$ / LSU |
| `chk_*`, `pma_*`, `pmp_allow_i` | the PMA and PMP checkers |
| `md_*` | the RV64M multiply/divide unit |

EX stalls on `md_*` until `md_done_i`, so a multiply cannot complete out of
order and needs no completion channel. When one of these blocks arrives, replace
its tie-off — not the testbench.
