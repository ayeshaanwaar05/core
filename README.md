# `core/` — the assembled S1 core and its RV64I test

The five-stage RV64 core (from `github.com/ayeshaanwaar05/core`), with an integration testbench that
runs **every RV64I instruction** through the whole pipeline, IF to WB, and checks every retirement
against **spike**.

## What lives here, and what does not

```
rtl/pkg/s1_pkg.sv       shared types and constants; compiled first
rtl/common/             meds_s1_sram (identical to ../rtl/common/)
rtl/modules/            one module per file: fetch, rvc_expand, id, decode, hazard,
                        regfile, ex, alu, mem, wb  (no CSR file: see below)
rtl/top/s1_core.sv      wires the stages together; everything external is a port
verif/tb_s1_core.sv     integration testbench: RV64I vs spike, over RVFI
verif/tb_csr_model.sv   minimal CSR stand-in for the testbench -- NOT the CSR file
verif/tb_s1_hazard.sv   unit testbench for the hazard unit
verif/rv64i_full.s      test program 1: every RV64I instruction (assembly)
verif/sort.c, crt0.s    test program 2: five sorting algorithms (C, gcc -O2 -march=rv64i)
verif/gen.py            builds the image and the expected results from the toolchain
verif/prog_<p>.svh      GENERATED by gen.py, and committed, with <p>.img.hex and
                        <p>.exp.hex (the image and the expected retirements)
verif/verilator.vlt     every lint waiver, scoped by file, each with its reason
Makefile                lint, test, test-unit, prog
```

Not here: the **CSR file** (another project builds it), the I$/D$, the PMA/PMP checkers and the
RV64M unit. The core declares them as ports and the testbench stands in for them (below).

The CSR file connects through `csr_addr_o/re_o/we_o/rdata_i/illegal_i` (EX's side-effect-free
query), `csr_commit_o` (the only write, from WB), `trap_req_o`, `mret_o`, `trap_vec_i`, `mepc_i`,
`priv_i`, `priv_data_i`, `irq_valid_i`, `irq_code_i`, `instret_o` and the `perf_*_o` event lines.
It owns the PMP CSRs and the counters. `tb_csr_model.sv` implements only `mstatus` (MIE/MPIE/MPP),
`mtvec`, `mepc`, `mcause`, `mtval`, `mscratch`, `minstret`, `pmpaddr0` and `pmpcfg0` -- what the test
program's trap handler needs -- so ECALL, EBREAK and MRET can still be checked against spike. Module contracts are in MEDS-S1's `docs/modules/s1_*.md`;
MEDS-S1's `docs/modules/s1_core.md` lists where this core departs from the SPEC.

## Running it

```bash
make lint        # lint + elaborate the RTL, -Wall
make test        # each program vs spike: ideal memory, then 16 random-stall seeds
make test-unit   # tb_s1_hazard
make all         # all three
make prog        # regenerate verif/prog_*.svh and *.hex after editing a program (host step)
```

Run against the Verilator the MEDS-S1 gate installs (5.020), not a newer local one:

```bash
podman run --rm -v "$PWD:/w:z" -w /w --entrypoint /bin/bash \
  docker.io/verilator/verilator:v5.020 -c 'make all'
```

Current result on 5.020 (also clean on 5.036):

```
make lint       lint clean
make test       rv64i_full: 17 runs, ~6300-6600 checks each, all PASS
                sort:       17 runs, 14745 retirements each, all PASS
make test-unit  tb_s1_hazard  === PASS : 26675 checks ===
```

One run by hand: `./obj/tb_s1_core [+stall] [+verilator+seed+N] [+v]`. `+v` prints every failure
instead of the first 30.

## How the test is trustworthy

Nothing in the expected results is written by hand.

```
verif/rv64i_full.s
   │  riscv64-unknown-elf-gcc -march=rv64i_zicsr, linked at 0x80000000
   ▼
 rv64i_full.elf ──► objcopy -O binary ──► image (text + data)        → memory
   │
   └──► spike --isa=rv64i_zicsr --priv=mu -l --log-commits
            │  runs to the program's tohost write
            ▼
        per retirement: pc, insn, privilege, rd and value, memory address/mask/data;
        trapping instructions rebuilt from spike's `exception` lines
   ▼
 verif/prog_rv64i_full.svh  +  rv64i_full.img.hex  +  rv64i_full.exp.hex
```

`gen.py` refuses to write `prog_rv64i_full.svh` unless all 52 RV64I instructions retired (it reads the
mnemonics from `objdump`), so the coverage claim is checked, not asserted. The current program
retires 392 instructions: 4 traps, 57 loads, 29 stores, 10 in U-mode. The per-instruction counts are
in the header of `prog_rv64i_full.svh`.

## The sorting workload

`verif/sort.c` is compiled with `gcc -O2 -march=rv64i`, so the core runs what a compiler emits:
stack frames, recursion, calls and returns, and every load/store width. It sorts 32 elements five
ways: quicksort (recursive, `int64_t`), insertion sort on a copy (`int64_t`), shell sort
(`uint32_t`), bubble sort (`int16_t`) and counting sort (`uint8_t`). The data comes from xorshift,
since RV64I has no multiply.

It checks itself: the two `int64_t` sorts must agree, every array must be sorted, and a checksum
proves no element was lost. `main` returns 0 only if all hold, and `crt0.s` writes
`(code << 1) | 1` to tohost. `gen.py` refuses a program whose spike run fails that check, and the
testbench requires tohost == 1. Independently, all 14,745 retirements (2,539 loads, 1,689 stores)
are compared against spike. With ideal memory it runs in 21,207 cycles (IPC about 0.70). Planting a
bug in the ALU's arithmetic right shift makes it fail at the first `srai`.

## What each retirement is checked for

Against spike: `order`, `pc_rdata`, `insn`, `mode`, `trap`, `rd_addr`, `rd_wdata`, `pc_wdata` (a trap's
is the handler, an MRET's is `mepc`), `ixl`, and the memory access — address and byte mask for a
load, address, mask and data for a store, and no access for everything else.

Against a shadow register file built from spike's own writes: `rs1`/`rs2` address is the field or
0, and the value is the architectural one. That checks the operand **EX actually used** — forwarding
the wrong value can still produce the right result.

At the end: the program reached its spin, wrote tohost, raised no store error, dispatched no
multiply and issued no FENCE.I.

## What the program covers

All 52 RV64I instructions, with their corner cases: largest and smallest immediates, signed
overflow, INT64_MIN, shift amounts using bit 5 (64-bit) or ignoring it (W forms), W forms with
garbage in the upper half, LUI/AUIPC with bit 31 set, every load width signed and unsigned, positive
and negative offsets, a load to x0, a write to x0.

And the pipeline mechanisms behind them: RAW at distance 1, 2 and 3 (EX/MEM forward, by-value
forward, register-file bypass); load-use into an ALU op, an address, store data, a branch and a
JALR; store-buffer forwarding from one and from four stores, youngest byte wins, partial forward
plus bus merge; more stores than buffer entries; FENCE drain; every branch condition taken and not
taken, forward and backward (so BTFN is right and wrong in both directions); JAL/JALR forward,
backward, odd target, negative offset, rd = rs1, no link; a mispredicted branch behind a load still
in flight; ECALL from M and from U, EBREAK, MRET to U and back to M, `minstret` across traps.

## The memory model and the stalls

One byte array sits behind both I2 ports, as DRAM does. With `+stall` each port withholds `ready`
about a quarter of the time and delays each response by 0–4 extra cycles (`$urandom`, seeded by
`+verilator+seed+N`). Every cycle both ports are protocol-checked: a presented request stays
presented with an unchanged payload until accepted (R-C10), and there is never a second request
outstanding (INTERFACES.md I2, v1).

The stalls are not decoration: with ideal memory the first two bugs below never fire.

## Bugs found and fixed

| Where | Bug | Seen as |
|---|---|---|
| `s1_id` | an EX mispredict cleared the ID/EX register, which holds the branch itself; if MEM was busy that cycle the branch was lost | under stalls, the `beq` behind a load never retired |
| `s1_hazard`, `s1_mem`, `s1_core` | a load waiting on the D$ in MEM/WB was invisible to the hazard unit | under stalls, stale operands for loads and stores |
| `s1_core` | the same blind spot let a CSR read run ahead of an older, unfinished load | found by reading, not by the test; closed with the fix above |
| `s1_wb`, `s1_core` | `minstret` counted trapped ECALL/EBREAK, which do not retire | `csrr minstret` one too high after each trap |
| `s1_wb` | RVFI `mode` fixed at M | wrong mode on every U-mode retirement |
| `s1_wb`, `s1_ex`, `s1_mem` | RVFI `rs1_rdata`/`rs2_rdata` fixed at 0 (INTERFACES.md I6) | every operand check |
| `s1_wb` | RVFI `pc_wdata` for MRET was pc+4, not `mepc` | MRET retirements |

Every row except the CSR one was reproduced by this testbench on the unmodified RTL before it
was fixed.

## Also changed

- `s1_pkg`: removed what nothing used — `md_req_t`, `md_rsp_t`, `mstatus_t`, `MUL_LAT`, `EV_NONE`,
  six exception codes the core never raises, and the dead fields `decoded_op_t.instr`, `aq`, `rl`
  (`ex_mem_t.aq`, `rl` too). Added `rs1_rdata`/`rs2_rdata` to `ex_mem_t` and `mem_wb_t` for RVFI.
  `decoded_op_t.cbo_op` is kept on purpose: it is unused only because Zicbom/Zicboz are not executed.
- `s1_ex`: removed the `ex_redirect_tag_o` port, which nothing consumed.
- `s1_regfile`: packed-array ports instead of unpacked, which Verilator 5.020 can miscompile.
- Lint waivers moved off the command line into `verif/verilator.vlt` (R-L2).
- Module headers point at files that exist; status tags no longer claim COMPLETE where only RV64I
  is verified.

## Not tested here, and why

| | |
|---|---|
| RV64M | `md_*` is external and tied off; the testbench asserts no multiply was dispatched |
| RV64A, Zicbom/Zicboz | not RV64I; CBOs are decoded but not executed (see `s1_core.md`) |
| RV64C | not RV64I; `s1_rvc_expand` is tested through MEDS-S1's `verif/unit/tb_s1_fetch.sv` |
| interrupts, FENCE.I | not RV64I |
| misaligned and faulting accesses | the core raises access faults (P3), spike misaligned exceptions; needs the real PMA/PMP checkers to be meaningful |
